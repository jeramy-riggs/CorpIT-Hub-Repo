DLP Incidents

Confirmed DLP violations from Workflow Automation — who triggered what, severity, and status. Click a row for the full incident record.

ⓘ What counts as a DLP incident? ▾
An incident is one specific event: someone tried to send protected data out — a loan number, GLBA/financial data, SSN — it matched one of our ZIA DLP rules, and that rule is set to forward the match into Workflow Automation. Each incident is one transaction: who sent it, what rule matched, how severe, and its follow-up status.
✔Uploading / pasting / emailing content with loan numbers or GLBA data that trips an enabled DLP rule with forwarding on
✔Both blocked and allowed-but-flagged sends — an incident records the match, not just blocks
✘Ordinary blocked websites (gambling, malware, etc.) — those live in Web Activity, not here
✘DLP rules that only send an email alert to the auditor mailbox — alert ≠ incident
✘Firewall or security blocks with no data-loss match
Heads-up for our tenant: today our DLP rules alert by email only — none forward into Workflow Automation yet. This list stays empty until forwarding is enabled per rule in ZIA (Policy → Data Loss Prevention → rule → incident settings). For DLP hits from the web logs in the meantime, use Web Activity → 🔒 DLP.
